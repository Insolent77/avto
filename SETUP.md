# GRAPHITE — мобильная запись в детейлинг

Рабочий первый вариант для детейлинг-студии в России: клиент выбирает услугу, дату, время и оставляет имя и телефон. Заявка резервирует конкретный бокс на всю длительность работы. Мастер видит её в кабинете, подтверждает, отмечает выполнение или отменяет. Мастер задаёт рабочую неделю и отдельные выходные.

## Два режима

- **Опубликованная демонстрация GitHub Pages** — статический интерфейс. Данные только в localStorage этого браузера. Демо-кабинет открыт; вводите вымышленные контакты. Между разными устройствами записи не передаются.
- **Серверная версия `node server.mjs`** — реальная общая SQLite-база и защищённый кабинет. Запись с телефона клиента доступна мастеру на другом устройстве через один и тот же сервер. Эта версия подготовлена и проверена локально, но ещё не размещена на сервере клиента.

Нельзя размещать только папку `dist` и считать, что получилась полноценная система записи. Для реальной работы нужен серверный API с базой.

## Локальный запуск на Windows

Нужен Node.js 24+. Внешних npm-зависимостей нет.

```powershell
cd ./avto
$env:OWNER_PASSWORD = Read-Host 'Придумайте пароль мастера от 16 символов'
$env:NODE_ENV = 'development'
npm start
```

Откройте `http://127.0.0.1:8787`. Значок профиля справа сверху открывает вход мастера. Пароль не имеет значения по умолчанию: без настройки `OWNER_PASSWORD` вход отключён. Сервер привязан к 127.0.0.1, пока не указан другой HOST. Для теста между двумя устройствами используйте один доступный сервер; локальный адрес компьютера на телефоне не является адресом этого сервера.

Альтернатива: скопируйте `.env.example` в `.env`, задайте пароль и `NODE_ENV=development`, затем `node --env-file=.env server.mjs`. Файл `.env` не отправляйте в Git. После остановки локального процесса без сохранённого env задайте пароль повторно.

```powershell
npm test
```

Только для визуальной демонстрации: `node preview.mjs`, затем `http://127.0.0.1:8788`.

## Что настроить под клиента

1. В `dist/business.json`: имя, описание, адрес вместо демонстрационной строки, услуги, длительность, цены и количество боксов. Часовой пояс первой версии — Москва, UTC+3; для другого региона нужно согласованно изменить расчёт дат в `domain.js`, подписи интерфейса и конфигурацию, а не только одну строку.
2. В `dist/app.js`: фото в hero. Текущее фото — иллюстрация, не портфолио реальной студии. Замените его согласованной фотографией клиента. Для независимости от внешних источников храните фото локально в `dist` и уберите внешнюю загрузку шрифта из CSS.
3. В `dist/index.html`, `manifest.webmanifest`, `icon.svg`: метаданные, название приложения, иконка и логотип. Для устойчивой установки на телефоны добавьте PNG 192/512 и apple-touch-icon 180 и проверьте на реальных устройствах.
4. Через кабинет мастера: рабочие дни, часы и выходные.
5. До сбора реальных контактов: реквизиты оператора, контакты для обращений, утверждённая политика обработки данных и условия согласия. Текущий текст в форме является шаблоном.

Для первого клиента создавайте отдельную папку и отдельную БД, а при размещении через Sites не копируйте `.openai/hosting.json` и Git-метаданные текущей демонстрации. Новому клиенту нужен собственный проект, адрес, секреты и резервные копии. Не создавайте общую клиентскую БД в этой реализации: здесь нет многопользовательской изоляции между студиями.

## Передача и размещение у клиента

Подготовлен вариант Node.js + SQLite + Caddy + Docker Compose. Файлы: `Dockerfile`, `compose.yml`, `Caddyfile`. Контейнеризация подготовлена, но в этой сессии не запускалась.

1. Создать аккаунт хостинга на владельца студии. Для первого российского клиента рекомендую сервер в РФ и согласование требований к обработке персональных данных до запуска. Стоимость сервера выбирается по актуальному тарифу провайдера.
2. Зарегистрировать домен на клиента либо взять поддомен существующего домена, например `booking.имя-студии.ru`. Бесплатный технический адрес тоже возможен, если его выдаёт выбранный хостинг. Домен и хостинг — разные услуги.
3. На сервере установить Docker Engine и Compose по официальной инструкции для его ОС. Загрузить эту папку без `.env`, тестовых БД и Git-метаданных Sites.
4. На сервере создать `.env` из `.env.example`: уникальный длинный пароль мастера и `DOMAIN=booking.example.ru` с реальным адресом. Закрыть доступ к `.env` другим пользователям сервера. Compose сам выставляет production, HOST, PORT и путь к БД.
5. В DNS создать A-запись выбранного имени на IPv4 сервера; AAAA добавлять только при настроенном IPv6. Открыть входящие 80/443. Порт приложения 8787 наружу не публиковать.
6. Выполнить `docker compose up -d --build`. Caddy запросит сертификат HTTPS после правильной настройки DNS и сетевого доступа. Проверить сертификат и `docker compose logs`. В production cookie мастера передаётся только по HTTPS.
7. Пройти реальную тестовую запись с одного устройства, войти мастером с другого, подтвердить, проверить отмену, выходной и попытку занять все боксы. Проверить отсутствие данных других клиентов без авторизации.
8. Настроить ежедневный backup и хранение копий вне сервера. Проверить восстановление. После этого включать реальные записи.
9. Передать клиенту домен, аккаунт хостинга, пароль мастера, исходники и короткую инструкцию. Разместить ссылку в карточках бизнеса, соцсетях и QR на стойке. Согласовать, кто оплачивает продление и кто отвечает за обновления и восстановление.

### Резервная копия

Для локальной серверной версии:

```powershell
node backup.mjs C:\backups\graphite-2026-11-06.sqlite
```

Скрипт делает SQLite-снимок через VACUUM INTO и проверяет целостность; файл назначения не должен существовать. Папка назначения должна быть доступна для записи. Для Docker: загрузить `backup.mjs` в контейнер или добавить его COPY в Dockerfile, выполнить его с DB_PATH=/app/data/bookings.sqlite и вынести полученную копию из Docker volume. Автоматический график и внешнее хранилище ещё нужно настроить на сервере. Простое копирование работающего `.sqlite` без учёта WAL не используйте.

Восстановление: остановить приложение, сохранить прежнюю БД вместе с её WAL/SHM на случай отката, разместить проверенный снимок как основную БД с правильными правами и перезапустить. Сначала проверить процедуру на отдельном экземпляре. Не удалять Docker volume при обновлении: там реальные записи.

## Ограничения первого варианта

- Работы в пределах одного дня; шаг 30 минут; запись на 60 дней вперёд. Для оклейки и многодневного детейлинга потребуется расширить модель занятости.
- Один бизнес, одинаковые по возможностям боксы, один пароль владельца. Смены отдельных мастеров и разные типы боксов пока не реализованы.
- При изменении часов уже принятые заявки сохраняются. Согласовывайте их перенос отдельно.
- Услуги и цены редактируются в конфигурации, не через кабинет. Сохранённая цена существующей записи остаётся прежней.
- Контакты видны мастеру и обладателю секретного токена своей записи. Клиентский токен хранится в браузере; после его очистки автоматическое восстановление доступа не реализовано.
- Заявки сразу занимают время и ждут подтверждения. Автоматического истечения неподтверждённых заявок нет.
- Нет SMS, Telegram, email, push, AI-чата, оплаты и автоматического переноса. Кабинет опрашивает сервер раз в 15 секунд; закрытый кабинет не уведомляет мастера. ICS добавляет событие, но не синхронизирует последующие изменения.
- Есть manifest и инструкция добавления на экран; офлайн-режим и service worker отсутствуют. Установка и standalone на физических iPhone/Android ещё не проверены.
- Ограничение запросов и сессии находятся в памяти одного процесса. Эта версия рассчитана на один экземпляр Node, не на горизонтальное масштабирование. Перезапуск завершает сеансы владельца, но сохраняет записи.
- Нет восстановления пароля через email, расширенного аудита и автоматического удаления по срокам хранения. Для первого живого клиента эти эксплуатационные процедуры нужно согласовать и настроить.

## Бесплатный и платный варианты

**Бесплатная демонстрация:** статический сайт на техническом адресе; подходит для показа дизайна. Демонстрация GitHub Pages публикуется из dist и использует данные браузера.

**Бесплатный запуск с общей базой:** возможен через бесплатные облачные тарифы, например Cloudflare Pages + Supabase Free, но для данного Node/SQLite-бэкенда нужна адаптация API и базы, это другой вариант развёртывания. Нельзя просто загрузить `server.mjs` на Pages. У Pages статические запросы бесплатны; функции имеют отдельные лимиты. Supabase Free предоставляет 500 MB БД, ограничивает число активных проектов и может приостановить неактивный проект через неделю. До использования для российских клиентов отдельно оценить требования к месту хранения данных и доступность сервисов из целевых сетей.

**Платный запуск:** сервер для готового Node/SQLite-приложения плюс домен при необходимости. Домен оплачивается с продлением; сервер обычно помесячно. Уточнять цену продления домена, backup и доплаты, а не только акционную цену первого месяца. Supabase Pro как альтернативная архитектура начинается от $25/мес по проверенному тарифу; это не обязательная покупка для текущей реализации.

**Продажа:** отдельно назвать стоимость настройки и передачи, регулярные расходы инфраструктуры и стоимость сопровождения. Разовая продажа за 3 500 ₽ из ролика — пример автора, не расчёт достаточности поддержки. Можно выставить свою цену настройки, а хостинг и домен клиент оплачивает напрямую. Бессрочную бесплатную поддержку в разовую цену не включать без расчёта.

Источники, проверены 6 ноября 2026: [Cloudflare Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Supabase pricing](https://supabase.com/pricing), [приостановка Supabase Free](https://supabase.com/docs/guides/platform/free-project-pausing), [Timeweb Cloud VPS](https://timeweb.cloud/services/vds-vps).
